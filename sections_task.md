# Задание: несколько разрезов в одной сцене

Цель: показывать в Isoliner3D несколько разрезов одновременно, каждую
ленту со своим чертежом. Сейчас это невозможно, потому что чертёж ничем
не связан с линией, вдоль которой он построен.

Работа делится на две части. Основная в Isoliner, там заводится связь.
Ответная в Isoliner3D, там она используется. Порядок именно такой:
пока в данных нет поля связи, показывать нечего.

## Контракт

Строковое поле **`sec_id`**, до 32 символов, одинаковое значение
в определении разреза и во всех слоях его чертежа.

- В слое **Определение разреза** поле добавляется к существующим `vex`,
  `step`, `zmin`, `zmax`. Один объект линии равен одному разрезу.
- В каждом выходном слое чертежа (пласты, скважины, рамка, оси, подписи)
  поле идёт первым и заполняется тем же значением.
- Значение задаётся пользователем в параметрах инструмента. По умолчанию
  `S1`, при нескольких линиях `S1`, `S2` и так далее по порядку объектов
  в слое линий.
- Поля нет или оно пустое: поведение прежнее, один разрез. Обратная
  совместимость обязательна, старые проекты ломаться не должны.

## Часть 1. Isoliner

1. Добавить `sec_id` в поля определения разреза и во все выходные слои
   чертежа.
2. Добавить параметр **Идентификатор разреза** в инструмент построения
   разреза по линии.
3. Снять ограничение одной линией. Общая функция чтения определения
   сейчас берёт геометрию первого объекта и на этом останавливается.
   Нужна работа по всем объектам слоя линий: на каждый строится свой
   чертёж со своим `sec_id`.
4. Вертикальный размах `zmin` и `zmax` считать **по каждой линии
   отдельно**, а не общий на слой. Сейчас рамка одна на прогон, и при
   нескольких линиях разрезы разной глубины получат чужой масштаб.
5. Проверить инструменты, которые принимают определение разреза
   на вход (проекция скважин, проекция на несколько разрезов и прочие):
   они тоже читают первую линию и должны научиться выбирать нужную
   по `sec_id`.

Headless-тесты:

- поле `sec_id` присутствует в определении и во всех слоях чертежа;
- значение совпадает во всех выходах одного прогона;
- слой из трёх линий даёт три чертежа с разными `sec_id`;
- у каждого чертежа свои `zmin` и `zmax`, посчитанные по своей линии;
- слой без `sec_id` на входе обрабатывается по-старому, без ошибки.

## Часть 2. Isoliner3D

1. Для каждой линии определения искать слои чертежа с совпадающим
   `sec_id` и накладывать на её ленту только их.
2. Поля нет ни в определении, ни в чертеже: прежнее поведение, один
   чертёж на все ленты.
3. Поле есть, но совпадения не нашлось: лента остаётся без чертежа,
   причина в журнал. Молча подставлять чужой чертёж нельзя.
4. `zmin` и `zmax` брать из полей своей линии, они уже читаются.

## Чего не делать

Не связывать по внутренним идентификаторам объектов QGIS. Они не
переживают пересоздание слоя.

Не сопоставлять по порядку, первая линия к первому чертежу. Работает,
пока порядок совпадает, и молча врёт, когда разойдётся.

## Перед началом

Уточнить, что уже есть в текущей версии Isoliner: возможно, поле связи
появилось вместе с проекцией на несколько разрезов, и заводить его
заново не нужно. Проверяется по таблице атрибутов слоя определения
разреза и любого слоя чертежа.

Контракт записать в AGENTS.md обоих проектов одинаковым текстом.
